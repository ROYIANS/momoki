# Research: dsh (deepseek-harness) Host / UI separation

- **Query**: How does `/Users/xiaomengdao/WebstormProjects/deepseek-harness` (dsh) separate Agent execution from the UI? Process boundary and lifecycle, IPC/protocol, durable-state ownership, approvals/grants/MCP/jobs across the boundary, reconnect/reattach, drafts/pending sends; what is portable to a Tauri + WebView app whose ProductStore is in the WebView.
- **Scope**: internal (read-only on reference repo)
- **Date**: 2026-10-16
- All paths below are relative to `/Users/xiaomengdao/WebstormProjects/deepseek-harness` ("dsh") unless prefixed `aifenjing`.

## Findings

### 0. One-paragraph model

dsh = **a complete Node "Host" (Cordis plugin tree: agent loop, tools, sessions, jobs, MCP, approvals, credentials, HTTP+WebSocket server)** + **a pure browser "Client" (React UI)**. The Electron app is a *thin shell* that spawns the Host as a child process (Electron-as-Node), loads the packaged Web UI from a custom protocol, and bridges UI→Host over authenticated HTTP/WebSocket. The Web UI is identical in browser (`dsh web`) and Electron; the shell adds only native chrome (window, tray, quit confirmation, updates, folder picker). `docs/architecture.md:55-60`, `apps/desktop/README.md:35`.

### 2. IPC / protocol between UI and Host

Three planes, deliberately separated:

1. **Node IPC (shell ⇄ Host)** — *lifecycle/control only*: `ready{url,injections}`, `fatal{message,diagnostic}`, `shutdown`, `shutdown-complete`, `quit-inspection`, `update-tasks`, `platform-session` (`host-process.ts:8-37`, `apps/desktop-host/src/index.ts`). Credentials for the embedded Platform view travel here, never to the renderer (`platform-session.ts:1-10`, README "Platform documents").
2. **Electron IPC (renderer ⇄ main)** — *native affordances only*: boot, directory picker, shortcuts, update presentation, browser-guest leases, etc. (`apps/desktop/src/ipc.ts:8-34`; preload `preload-app.ts`). "No renderer receives filesystem access, raw Electron IPC, a shell, or arbitrary pnpm arguments" (`apps/desktop/README.md:143`). Sender validated: `assertDesktopSender` (`main.ts:691`).
3. **HTTP + WebSocket (renderer ⇄ Host)** — *all product traffic*. UI is served from `dsh-app://app/`; `protocol.handle(SCHEME)` serves static assets from the bundle and forwards everything else to the Host with the Host's auth cookie injected main-side (`main.ts:667-682`, `forwardWebRequest`); WebSocket requests (`ws://127.0.0.1/*`) get `origin`/`cookie` rewritten in `webRequest.onBeforeSendHeaders` (`main.ts:715-726`) — the renderer never holds the credential. UI learns the WS origin from boot `streamBaseUrl` (`main.ts:694`, `packages/client/connection/README.md:30`).
   - **RPC**: typed "Remote" calls — unary = HTTP `POST /api/...` JSON (+ multipart for binary results); streams = multiplexed WebSocket `/api/remote.mux` (`client/connection/README.md:32-34`). Contracts generated by Typert (`packages/typert`, `packages/api/gateway`). Docs: `docs/api-gateway.md`.
   - **Events**: one internal `$events` logical stream per answering client: Host sends `{type:'ready', clientId, host:{home}}` **then** events; the Client publishes the connection generation and runs baseline reads only after `ready` (`client/connection/README.md:58`; `api/gateway/README.md:47`).
   - **Auth/trust**: random per-launch token → signed host-only `HttpOnly` cookie; Host/Origin allowlist (DNS-rebinding defense) (`client/connection/README.md:41-47`). Principal/`Peer` model with `interactions: 'answer'|'none'` (`:49-51`).
   - **Controllers as API surface**: `api/session-controller`, `job-controller`, `settings-controller`, `workspace-controller`, `terminal-controller`, `account-controller`, `workspace-files` (`packages/api/*`).

### 3. Where durable state lives (all Host-side)

- **Session = append-only event log is the single source of truth**; model history and the UI transcript are *derived* from it (`docs/architecture.md:118-121`; `docs/subsystems/session.md:5`). The UI keeps no authoritative copy; it holds a windowed journal built from `follow`/`page` (`packages/api/session-controller/README.md:30-32`, `:54`).
- **Persistence seam**: `ctx.sessionPersistence` (`create/open/stat/list`, per-session `SessionHandle` read/append/flush/close; single-writer lease) — `docs/subsystems/persistence.md:7-11`; shipped backend JSONL with checksummed zstd frames, atomic materialization, per-batch `fsync`, torn-tail truncation (`persistence.md:331`). Write-behind batching window; only resolved `flush` is a durability barrier (`persistence.md:72`, `:104-106`).
- **Crash recovery is log-level, not process-level**: an open trailing turn is *not* truncated; on resume, agent-loop appends synthetic `turn/end(interrupted)` and synthetic tool results (`TOOL_NOT_STARTED` / `TOOL_OUTCOME_UNKNOWN`) (`persistence.md:110`; `docs/subsystems/session.md:713-718`; `packages/core/session/README.md:123`, `:171`; `packages/core/agent-loop/README.md:116`). Stream chunks not yet settled are lost on hard crash (`docs/architecture.md:120`).
- **Other durable state, also Host-owned**: non-session data via `packages/storage/*` (workspaces, sidecars); credentials in `$DSH_HOME/.credentials.yaml` (`client/connection/README.md:43`); settings; profile under `$DSH_HOME/profiles/desktop` (exclusive to the Desktop process via the single-instance lock, `apps/desktop/README.md:118`, `:141`). CLI and Desktop share `$DSH_HOME` product data (`README.md:364`).
- **Shell-owned state (outside Host)**: `userData/desktop/settings.json`, `keybindings.json`, `background-close-confirmed`, crash reports, updater cache (`apps/desktop/README.md:62`, `:89`, `:287`; "Host-independent ownership").
- **Cold vs. loaded sessions**: list reads stored headers/projection cache only and never activates an Agent (`session-controller/README.md:34`); prompt/queue/rename may resume (`:34`); an in-flight turn only exists for sessions *loaded* in the Host process (quit inspection counts loaded sessions only, `quit-inspection.ts:16-22`, `README.md:79`).
- **Session↔agent resolution**: Session Controller `lookup` reuses a live Agent or auto-resumes a cold one, dedupes concurrent resumes (`docs/api-gateway.md:132`); `session.create` reuses a blank session and keeps the writer lock (`session-controller/README.md:44`); `session/writer-held` error if another process holds it (`:65`).

### 4. How approvals / grants / MCP / jobs cross the boundary

- **Approvals** (`docs/subsystems/approval.md`, `packages/interaction/user-approval/README.md`):
  - Host-side `ctx.approval.request()` is an in-process *waterfall* `approval/request` (`approval.md:5`; `user-approval/README.md` "Requesting a decision"). Outcomes closed & fail-closed: `allowed-once | rejected | cancelled | unavailable`; no answerer ⇒ `unavailable` ⇒ tool denied (`approval.md` "Identity and outcome").
  - The waterfall is **forwarded to the UI** as an Agent-scoped Remote event (`packages/api/remotes/src/remote-events.ts:27` `{ event: 'approval/request', mode: 'waterfall' }`; also `:52` `user-questions/request`). UI (`packages/client/ui-approval`) renders it into the composer and replies; reply must come from the *same Peer's* event stream (`api/gateway/README.md:49`). Only `interactions:'answer'` owner Peers receive/answer; non-owner Peers get broadcasts only (`:47`, `:49`).
  - Abort/withdraw ⇒ `cancelled`, late answers discarded (`user-approval/README.md`). Every ask/decision is an audit pair `approval/asked`/`approval/decided` in the session log (`approval.md` "Identity").
  - Grants are **one-shot only** in the UI ("transient decisions only; persistent permission policy remains Host-side", `ui-approval/README.md:36`). Persistent policy = per-session `ask|never` as a durable `approval/policy` log event (`approval.md` "Per-session policy"), plus permission presets bundling sandbox+approval (`packages/interaction/permission-presets/README.md`).
  - Pending approval counts as active work for quit/update (`update-tasks.ts:8-15`: "turns waiting for approval").
- **Jobs** (`packages/jobs/jobs-local`, `packages/api/job-controller`): background jobs are **process-local** to the Host and "end when their owner or the harness shuts down" (`jobs-local/README.md:12`). UI sees them only as projections: `job.list` (whole-set frames re-sent after each coalesced commit — a reconnect's first frame is already the whole truth), `job.follow` (retained output from absolute byte offset, bounded tail), `job.kill` (human kill, logged as "cancelled by the user") (`job-controller/README.md` "Use this package"). Client keeps one stream per watched session/job, ref-counted.
- **MCP** (`packages/mcp/mcp-client/README.md`): MCP client lives entirely in the Host (stdio child processes or streamable-http); tools register on `ctx.tools` as `mcp__<server>__<tool>` (`:75`); auto-reconnect with doubling backoff 500 ms→30 s, 10 attempts, last-known tools remain listed but calls fail during outage (`:64-67`, `:93`). The UI has no MCP protocol knowledge; it only sees tool calls in the session log and settings via settings-controller.
- **Credentials/auth to UI**: renderer receives no tokens; Platform credential travels Node-IPC→main only (`platform-session.ts`, `apps/desktop/README.md:45`).
- **Event delivery guarantees**: forwarded events carry no projection/redaction (`api/gateway/README.md:92`); one-way notifications are *not* replayed after reconnect, only still-pending scoped waterfalls are (`api/remotes/README.md:79`; `api/gateway/README.md:90`). State needing reliable recovery uses "owner-provided query, cursor, or opening baseline".

### 5. Reconnect / reattach

- **UI-side generation model**: `ConnectionController` publishes `connecting/connected/disconnected`; a generation is visible only after the Host's `ready` item; retries with 50–100 % jitter and caps 500 ms→10 s; handshake warns at 3 s, aborts at 15 s; `offline`/`online` browser events suspend/resume; `connection.reconnect()` for immediate retry (`client/connection/README.md:58-64`). Gateway registers the WS upgrade route only after the app is ready (`api/gateway/README.md:41`), so a restarting Host cannot accept streams early.
- **Session reattach**: `SessionEventStream` opens `follow` *before* the initial page, publishes only contiguous `replace/prepend/append/settle-assistant` changes and repairs reconnect or sequence gaps via a tail page (`session-controller/README.md:54`); reconnect cancels previous projection reads and reloads requested ones (`:50`). Live assistant tokens: each opening carries `startedAfterSeq`, `nextIndex` and compact stream so partial streams resume (`:54`).
- **Pending approvals after UI reload**: pending scoped waterfalls replay with their event id (`api/gateway/README.md:90`, `api/remotes/README.md:79`).
- **UI (renderer) crash / reload**: shell sets `navigation = undefined` and reports fatal for any non-`clean-exit` render-process-gone (`main.ts:1112-1117`), `did-fail-load` (`:1104-1108`) and `preload-error` (`:1109-1111`) → same native recovery dialog; Host untouched. After a replacement Host authenticates, shell reloads the existing application URL so the page re-fetches port/cookie/boot injections (`apps/desktop/README.md:278`; `main.ts:546-552`). "The existing Web document resumes through the boot IPC response" (`main.ts:578`).
- **Host crash**: UI sees WS loss → `disconnected/connecting` retries; shell concurrently shows fatal dialog and offers relaunch (see §1). No hot reattach to a *new* Host in the same shell session except the update-failure path. After relaunch, in-flight turn is closed `interrupted` by log repair and sessions are resumed lazily.
- **Hidden window**: UI document stays alive while hidden, so stream/approval state persists with no reattach (`apps/desktop/README.md:69`).

### 6. Drafts and pending sends

- **Drafts are Client-local, not Host state**: `localStorage` key `dsh.conversation.<sessionId>`, persisted by the client store (`packages/client/ui-conversation/src/client/stores.ts:13` key, `:25` `persist: CONVERSATION_STORE_KEY`, `:45-62` `readConversationDraft`). Holds text + file/folder/Session reference chips; survives session switch and reload (`packages/client/ui-conversation/README.md:79`); moves between workspaces only during the synchronous prepare callback (`:83`). Window hide keeps the same document so drafts persist trivially (`apps/desktop/README.md:69`). Failed submit restores the draft if composer empty (`ui-conversation/README.md:107`).
- **Optimistic send / pending echoes**: Enter clears the draft immediately and sends as a detached attempt (`ui-conversation/README.md:105`). `session.beginSubmission` inserts a local echo into `SessionSnapshot.pendingSubmissions` *synchronously*, before serialization/prompt; placement (`transcript|queued|steering`) derived from running state and delivery mode (`session-controller/README.md:56`).
- **Correlation**: the prompt's `requestId` is the correlation id; Host echoes it as the durable user source's `rpcId`, including pending messages in the `inbox` projection (`session-controller/README.md:56`). Prompt with no text and no attachment is rejected before any append (`:34`).
- **Retirement rules**: queued echoes retire one animation frame after queue acceptance; identified failures/abandonment retire immediately; after reconnect, a replacement follow baseline withdraws receipt-confirmed echoes by accepted attachment references, unconfirmed ones stay pending; "Reconnecting between claim and admission can briefly omit that bubble; withdrawal confirms acceptance, not execution or failure" (`session-controller/README.md:56-59`). Accepted prompts/observed running survive list refresh and session-object replacement (`:52`).
- **Durable truth for in-flight input**: the Host `inbox` projection (durable, readable cold; `docs/architecture.md:109`, `agent-loop/README.md:120`) — so queued/pending messages survive UI loss; unsent *draft text* does not exist on the Host.

### 7. Portability notes to Tauri + WebView where ProductStore currently lives in the WebView

(Mapping of what exists in dsh, not recommendations on design.)

| dsh mechanism | Tauri/WebView analogue that exists in the same shape | Notes on what depends on Electron/Node |
|---|---|---|
| Host child process + Node IPC (`host-process.ts`) | Tauri sidecar (`tauri-plugin-shell` / `Command::sidecar`) or Rust `std::process` child; message channel = stdio JSON lines or loopback socket | dsh relies on Node `child_process` IPC (`stdio:'ipc'`, `process.send`, `disconnect` event) for ready/fatal/shutdown-ack and for auto-exit when the parent dies (`apps/desktop-host/src/index.ts:91`). Equivalent must be re-created (stdin EOF ⇒ shutdown). |
| `ready{url}` + OS-assigned port + auth cookie (`index.ts:30,103`; `main.ts:454`) | Same pattern works: sidecar prints ready JSON; shell/Rust holds the token | Cookie injection is done in Electron `protocol.handle` and `webRequest.onBeforeSendHeaders` (`main.ts:667-726`). Tauri has no equivalent request interceptor for WebView `fetch`/WS; token must come through a Tauri command/initialization script (dsh already has a `streamBaseUrl` injection for static pages, `client/connection/README.md:30`) or custom URI-scheme proxy. |
| Typed HTTP+WS RPC with `$events` ready-first generation, reconnect/backoff, replay of pending waterfalls | Transport-agnostic (plain HTTP/WebSocket); client lib `packages/client/connection` is browser code; `ClientTransportHooks.createWebSocket` exists for non-page carriers (`client/connection/README.md:34`) | Protocol is the portable part; it presupposes a Host that keeps state across UI reloads. |
| Single-instance lock before profile access (`single-instance.ts`) | `tauri-plugin-single-instance` | Ordering rule (lock before touching profile) is transferable. |
| Close-hides / tray / quit gate that asks Host what it would interrupt (`quit-confirmation.ts`, `quit-inspection.ts`) | Tauri `on_window_event(CloseRequested)` + `RunEvent::ExitRequested` + tray API; control request to Host sidecar with 2 s deadline, unknown⇒prompt | Active-task predicate is a pure function of Host state (agents running / inbox non-empty / jobs running|stopping / armed reminders): `update-tasks.ts:16-21`. |
| Session-end handling | Windows `WM_ENDSESSION`, macOS power-off notification | dsh handles via Electron `session-end`/`powerMonitor` (`main.ts:1092`, `:1247`); Tauri would need platform hooks. |
| Durable state in Host (event log + JSONL persistence + inbox + queue) | If ProductStore stays in WebView, the dsh split is inverted for: sessions/events, queued/pending input, approval policy, job list, MCP state. In dsh these are all Host-owned and the UI is a disposable projection (`docs/architecture.md:120`; `session-controller/README.md:30-32`). | Only *drafts, view prefs, panel sizes* are WebView `localStorage` in dsh (`ui-conversation/src/client/stores.ts`), plus Electron-userData shell prefs. |
| Crash semantics: Host crash ⇒ whole-app recovery dialog / relaunch, no live reattach; log repair closes open turn as `interrupted` with synthetic tool results | Rust-side supervision could replace "relaunch" with sidecar respawn, but dsh itself does not do this | Reusable concept is the *log-level repair* (`TOOL_NOT_STARTED`/`TOOL_OUTCOME_UNKNOWN`, `session.md:713`), independent of Node. |
| Approvals as Host waterfall with fail-closed outcomes + cancellation on abort + audit pair in log | Needs a Host that can park a pending request and re-present it on UI reconnect; dsh replays pending scoped waterfalls with the same event id (`api/gateway/README.md:90`) | One-shot grants only in UI; persistent policy is a Host log event. |
| Pending-send echo with `requestId` correlated to durable `rpcId` | Requires Host-side durable inbox keyed by `requestId` to dedupe/confirm after reconnect | Without a Host-owned inbox the "confirmed vs unconfirmed" reconciliation in `session-controller/README.md:56-59` has no source of truth. |

## Caveats / Not Found

- Did not find any automatic Host respawn-on-crash in dsh; crash handling is a native fatal dialog + whole-app `relaunch` (`main.ts:105`, `:513-515`), except the update-failure restore path (`main.ts:539-557`). The task prompt's "restart on crash" is therefore answered as: *supervised and surfaced, not auto-restarted*.
- Did not read `packages/api/gateway/src/*` or `packages/client/connection/src/*` source line-by-line; transport behavior above is taken from their READMEs (cited by line). Approval reattach behavior ("pending scoped waterfalls replayed") is from README text (`api/gateway/README.md:90`, `api/remotes/README.md:79`), not verified in code.
- MCP and jobs UI crossing is from READMEs (`job-controller`, `mcp-client`, `jobs-local`); no MCP-specific UI package was inspected.
- Draft storage evidence is `localStorage` in `ui-conversation/src/client/stores.ts`; whether the Electron shell keeps `localStorage` across restarts depends on Electron `userData` (README: Windows uninstaller removes it, `apps/desktop/README.md:260`); not independently verified.
- `apps/web` and `apps/cli` (browser/headless entry) were not inspected beyond what `docs/architecture.md` states.
