# 右侧栏承载复杂界面与表单

## Goal

复杂界面和表单统一放进右侧栏，不再用弹窗，也不再在对话流里填表单。弹窗只留给警告/确认，以及只有一个输入项的操作（如重命名）。本阶段只做规划，不改代码。

## Owner 已定原则（2026-10-20）

- 弹窗只用于：警告/确认（如确认删除）、单输入项（如重命名）。其余复杂界面放右侧栏。
- 表单不放在对话流里：生成提案、音乐生成、收尾总结、批量审阅都进侧边栏。
- 对话流只展示内容与状态；等用户动手的操作是输入框上方的行（已有的批量行、审批行）。
- 右侧栏行为参照 deepseek-harness（dsh）：占一列让出内容宽度、可拖宽、窗口太窄时变成覆盖层（owner 选「dsh 方式」，不是自动加宽窗口）。
- 长期记忆已存：`ui-modal-sidebar-principle`。

## Background（已确认事实）

- 现有机制：`app/layout/context-panel.tsx` + `ContextPanelHost.tsx`。同一时间只有一个活动面板，新的通过「离开守卫」协议替换旧的；每个面板注册自己的宽度（300/400/520）。
- 停靠条件：`surfaceWidth >= navigationWidth + width + 480`（内容区至少留 480px），否则面板变成覆盖内容的全宽面板。
- 已在用的面板：`TaskInspector`、`InstalledSkillsPanel`、`McpConnectionsPanel`、`MemoryContextDetails`、`AudioWorkspacePage`、`MusicWorkspacePage`、`MaterialDetailPanel`。
- 业务详情面板：`app/details/BusinessDetails.tsx`（目前只支持 `shot` 与 `asset`），带「返回来源」与拒绝协议。批量审阅弹窗通过 `openAfterModalRelease`（`AgentGenerationBatches.tsx`）交接给它，原因是弹窗与面板争抢焦点。
- 现状没有：自动出现、拖宽、同时多块内容（tab）。
- 现状顶栏（`app/layout/AppFrame.tsx:166`）是一条横跨窗口的 `app-topbar`：logo、后退/前进/导航开关、一个由各功能通过 `AppHeaderPortal` 塞内容进来的标题槽、兜底标题。下方 `app-frame-body` 才是 导航栏 | 工作面（内容 + 面板宿主）。右侧栏没有进入顶栏，面板头部是面板内部自己的一行（如「← 任务工作台 ×」）。
- 参照图：Codex 顶栏分三段，各自压在对应的列上，右段是面板的标签条（文件标签、+、展开、侧栏开关）；dsh 的面板同样没有独立头行，控件骑在标签条上。
- 弹窗盘点（读码，见 `../10-19-product-audit-direction/research/modal-vs-sidebar-audit.md`）：约 15 处应迁右侧栏，AlertDialog 确认类约 20 处保留；优先级前五：批量图片生成审阅、批量配音、素材导入、镜头变更提案 + 音频编排、槽位编辑 + 音色库。
- 对话流里仍有表单/按钮的：生成提案（`GenerationReview.tsx`）、音乐生成（`MusicGenerationReview.tsx`）、收尾总结（`TaskWrapup.tsx`）、桌面导入（`AgentDesktopMediaReport.tsx`）、MCP 核对（`AgentJobReport.tsx`），以及批量的「确认生成/保存草稿」留在审阅弹窗。来源：`../10-19-agent-queue-steer-parallel`（已归档）的未完成项。

## Requirements

1. **自动出现（owner 已定）**：agent 准备好需要用户审阅/填写的内容时，右侧栏自动展开，但不抢键盘焦点。用户关掉后，同一件事不再自动弹出；想看再点输入框上方对应行的「审阅」。
2. **同一时间一块面板（owner 已定）**：已有面板打开时，新内容不替换它，只在输入框上方多一行「审阅」，等用户看完点它再切换；面板空着才自动展开。沿用「离开守卫」与「返回来源」。标签页以后再说。
3. **范围（owner 已定）**：约 20 处弹窗与对话流里的表单一次纳入规划；实施分批、每批可独立提交与回滚，不赶进度。
4. **顶栏分三区，用分割线分开（owner 已定）**：
   - 左区（压在导航列上方）：快捷按钮——logo、后退/前进、侧栏开关。
   - 中区（压在内容区上方）：标题、重命名；右端是该页面的快捷按钮，打开右侧栏的开关也在这里。
   - 右区：仅在右侧栏出现时才有，放这块面板自己定制的操作按钮；没有就放标题，什么都没有就留空。右区宽度跟随面板宽度。
5. **弹窗只留两类**：警告/确认（AlertDialog）与只有一个输入项的操作（如重命名）。其余弹窗全部改为右侧栏。新增复杂弹窗应被测试拦住。
6. **对话流里不放表单**：生成提案、音乐生成、收尾总结、批量审阅（含「确认生成」「保存草稿」）进右侧栏；桌面导入、MCP 核对是单个动作，做成输入框上方的行。对话流里只留一行状态。
7. **右侧栏行为**：占一列让出内容宽度（参照 dsh）、可拖宽并记住宽度、窗口放不下时变成覆盖层；面板底部有固定的主操作区（确认/保存/取消）。

## Acceptance Criteria

- [ ] 顶栏分为左/中/右三区，区间有分割线；左区只有快捷按钮，中区有标题、重命名与右端快捷按钮（含打开侧栏），右区仅在面板打开时出现并跟随面板宽度。
- [ ] agent 准备好批量审阅/提案/音乐/收尾内容时，面板空着则自动展开且键盘焦点留在输入框；关闭后同一件事不再自动弹出；已有面板时不被替换，只在输入框上方多一行。
- [ ] 右侧栏可拖宽，宽度被记住；内容区至少保留既定最小宽度；放不下时变为覆盖层且不丢未保存内容。
- [ ] 批量图片/视频审阅、生成提案、音乐生成、收尾总结不再是弹窗或对话流里的表单，而是右侧栏内容；对话流里仅一行状态。
- [ ] 桌面导入的停止/核对、MCP 结果核对是输入框上方的行，消息区没有按钮。
- [ ] 审计清单里标为「改右侧栏」的约 15 处弹窗全部迁入右侧栏；保留的只有 AlertDialog 确认与单输入项（重命名等）。
- [ ] 有测试拦住新增的复杂弹窗（允许清单之外的 Dialog 使用即失败）。
- [ ] 迁移前后功能不回退：未保存草稿的离开守卫、焦点返回、键盘 Escape 关闭、屏幕阅读器标签保持；全量测试除需要 Rust 探针的原生测试外通过。
