## 二、调研额外发现

**Agent 并发的真实结构**
- 约束是「每个线程同一时间只有一个执行」，在四层各挡一次：输入框 `canSend`、页面 `sendLocked`、服务 `claim()`、数据库 `runBlocksThread`；批量另走内存预留 + Web Lock。不同线程之间已经可以并行。
- 因此「运行中批量」和「运行中排队/插队」不是改一个 disabled 标志，而是同一个架构问题：线程独占模型。获取锁会把同线程其他 running 的 run 标为 interrupted，三处假设要一起重设计。
- 图片批量只能由 Agent 工具创建，没有项目级的图片批量入口，也没有手动「生成」按钮。
- 插队的天然边界存在（tool 结果追加之后、下一次模型请求之前），但宿主没有注入用户输入的钩子；不能在 assistant tool_calls 与 tool results 之间插入，否则破坏协议信封。
- dsh 有现成参照：`next-turn`（排队）与 `next-step`（插队）两个持久收件箱，QueueDock 提供编辑/移除/转插队。

**生成与资源库**
- 没有任何工具/命令能把生成结果变成素材库条目；`MediaRecord.libraryRetained` 与 `promoteLegacyMaterial` 是现成挂钩。
- 媒体强归属项目（`projectId` 必填，`assertSlotMedia` 校验），跨项目靠复制；`"studio"` 伪项目已是共享归属者。
- 没有图片字段的位置：IP 档案、剧集/节拍。
- 视频只能生成到镜头 `clip` 槽位；视频模型仅 2 个（MiniMax H3、Veo 3.1 Fast）。

**业务线深度**
- 视频与音频脱节：`features/video` 没有任何引用音频/音乐，配音和 BGM 挂不到镜头上。
- Agent 没有任何导出/交付类工具（CSV、分镜板、交付包、WAV、项目 ZIP），但服务层已存在，补工具成本低。
- 音频导出只有 WAV；音乐是最薄的业务线（约 1.5k 行），无续写/翻唱/分轨。
- 无项目复制与模板；素材库搜索只是字符串包含，无语义搜索和自动打标。
- 应用内没有整集预览或剪辑（README 明说不提供）。

**Agent 稳定性与体验（未修）**
- E11 过渡批次（批次 6）没有提交：隐藏窗口里 WebView 崩溃无检测、Quit 在渲染进程 1 秒无应答时跳过草稿确认、有运行任务时退出/关闭无提示、草稿与失败发送记录只在内存、启动恢复全有或全无（一个线程坏数据使整个 App 打不开）。这些在 `review-E11` 中多为 P2，WebView 崩溃为 P1。
- UI/UX overhaul 批次 8/9 没做，没有改造后的真实界面截图验证；聊天 UI 仍有 `导入结果待核对`、`待核实`、`版本 N · 人工修订` 等内部术语。
- 素材库、IP、记忆、项目/分集、音频条目仍只有页面跳转，没有 Agent 并行详情。
- 外部 MCP 的只读工具也每次要审批；技能目录名必须 kebab-case 且等于 skill name（评审称「真实用户最先会遇到」）。
- 代码里没有 TODO/FIXME，也没有被 skip 的测试，已知限制只存在于文档。

## 五、owner 追加反馈（2026-10-19）

- 整体使用不舒服：运行频繁中断、很多事情做不了。
- 缺少好用的内置技能（技能目录名限制、MCP 只读工具也要审批等已在 Agent 问题清单里）。
- 设计原则：所有操作围绕输入框，对话消息内不应出现操作按钮。消息区现状：批量生成卡片约 43 处、任务收尾约 25 处、运行详情约 15 处、音乐生成审阅约 13 处、任务报告约 12 处点击入口（读代码统计）。
