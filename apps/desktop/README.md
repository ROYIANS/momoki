# Momoki desktop: shared product and native validation

The normal Tauri application loads the existing root React product, including
its Agent, pages and business commands. The normal product owns all shared
ProductStore tables in SQLite and copies imported media into its internal file
workspace. Native HTTP, file saving, external-browser links and storyboard
printing are centralized runtime services. The browser uses the same React and
business code with its own IndexedDB adapter. Synchronization remains subsequent
work; normal startup does not import old browser data or the historical SQLite
experiment.

The current contracts are in
[native-product-runtime.md](../../.trellis/spec/frontend/native-product-runtime.md).
Build the normal application with the local machine pnpm:

```sh
/Users/xiaomengdao/.nvm/versions/node/v24.11.0/bin/pnpm --dir apps/desktop build:app
```

See [desktop distribution](../../docs/desktop-distribution.md) for the supported
installer matrix and owner-controlled GitHub Release flow. The desktop workflow
only builds and packages: it does not run tests, quality checks or application
launch/smoke checks. Successful receipts say `packaged` and contain no passed
test claims. Source/version/host/tool/file/hash integrity remains checked; the
owner handles functional testing before publication. Separate local commands
below and GHCR quality remain available. The known native 64-turn Agent
continuation test can exceed 20 seconds; package-only delivery does not resolve
its performance.

The `--isolated-product` lane without `--sqlite-product` is an explicitly
separate IndexedDB reference. It is not the normal product storage owner.
The `--acceptance` frontend, storage CLI, lock probe and dedicated Tavily probe are
explicit test lanes. Their finite reports do not replace full product, live
supplier or other-platform acceptance.

## Storage API

`StorageWorker::create/open/restore` returns a single worker that owns a dedicated lifetime `writer.sqlite` SQLite `BEGIN EXCLUSIVE` connection and a separate `metadata.sqlite` connection. Owned `Job` values snapshot queued inputs. `submit` returns an `Operation` whose ID can be canceled directly through the atomic registry outside the work queue; `wait` returns the actual outcome. `close` marks the lifecycle ended immediately, cancels uncommitted work and serializes release behind cleanup. Every successful close call, including concurrent idempotent callers, waits for actual writer/thread release. Submission and Close admission share a registry lock, so shutdown cannot retain an unexecuted cancelable operation. A successful actual metadata COMMIT or backup-completion publication wins late cancellation.

The prototype tables are workspace, projects, assets, refs and intents. Workspace identity is a canonical UUID. `studio` is an exact virtual owner, never a project row. Assets use media/output kinds and the same canonical owned path. Missing/corrupt bytes do not remove records or timing. Import paths/source names are device-local/native inputs; portable records contain only exact references and reviewed metadata.

Create, backup and restore require a fresh destination and reject even an existing empty directory. `workspace.ready.json` and `backup.complete.json` are closed completion formats published last. Backup reserves the full queue, uses bounded SQLite backup steps and copies/hashes every snapshot-referenced asset. The final publication boundary independently rechecks the destination DB hash/schema/identity and all copied asset hashes after copying; restore performs the same check before its ready marker. There is no ready backup or restored root with a missing/corrupt verified closure. Completion serialization streams within the same 16 MiB budget enforced by its reader; overflow retains an incomplete target and never publishes completion. No writer/profile/credential data is portable.

## Feature-gated test CLI

Build with `test-hooks`; the CLI is excluded from normal release targets:

```sh
node apps/desktop/scripts/tools.mjs cargo build --manifest-path src-tauri/Cargo.toml --locked --features test-hooks --bin workspace_probe
apps/desktop/.tools/target/debug/workspace_probe create /absolute/new/workspace
apps/desktop/.tools/target/debug/workspace_probe open /absolute/existing/workspace
apps/desktop/.tools/target/debug/workspace_probe restore /absolute/new/root /absolute/complete/backup
```

One JSON request per stdin line, at most 256 KiB, yields one JSON line `{ok:true,value:...}` or `{ok:false,error:{code,message}}`. Startup emits `{ok:true,ready:true}`. Test CLI arguments are native-only and snake_case; portable output DTOs are camelCase and reject unknown fields.

```json
{"op":"saveProject","project":{"id":"project","title":"Fixture"}}
{"op":"import","source":"/absolute/fixture.wav","asset_id":"asset","project_id":"project","kind":"media","display_name":"fixture.wav","mime_type":"audio/wav","timing":{"id":"clip","projectId":"project","assetId":"asset","startSec":1.25,"durationSec":3}}
{"op":"state"}
{"op":"availability"}
{"op":"backup","destination":"/absolute/new/backup"}
{"op":"close"}
```

`submitImport` has the same fields as import and returns `operationId`; `cancel`/`wait` take `operation_id`. This permits cancellation while storage is blocked in a test hook. Hooks are enabled only in the feature-gated CLI or tests:

```text
--pause POINT --marker /absolute/new/marker --release /absolute/release
```

Marker creation signals that the same actual storage owner reached the point; a reviewer may SIGKILL that process or create the release file. Points: `intent-before-stage`, `partial-copy`, `copy-chunk`, `before-publication`, `link-before-unlink`, `published`, `precommit`, `postcommit`, `project-precommit`, `backup-step`, `backup-before-completion`, `backup-after-completion`, `restore-before-completion`, `restore-after-completion`.

Permanent tests actually kill child processes, then reopen twice. They distinguish uncommitted work from committed work and preserve source/unknown files. A two-link stage/final pair is accepted only when both names match recorded intent ownership and the same recorded device/inode. External aliases or ambiguous intent paths produce a focused error with bytes retained.

## Finite protection and evidence

All ordinary managed files reject symlinks and unexpected hard links. Opened root/database identities and every existing journal/WAL/SHM ordinary-file/link state are checked again before operations and commit. Strict versioned schema rejects explicit unknown indices as well as unexpected tables, triggers and views. Copy/hash uses at most 256 KiB buffers, source identity/size/mtime checks and fsync. Exclusive hard-link publication does not overwrite. Current code uses standard path-based OS opens, **not descriptor-relative/no-follow ancestor traversal**: a hostile OS user racing replacement between checks and opens is not prevented by these tests. Unknown files are never scan-deleted. A crash in the tiny stage-create/before-inode-record window deliberately leaves unproven bytes and rejects recovery rather than guessing ownership.

Actual process death is tested; physical power loss, network-filesystem semantics, other OSes, malicious database editors and large-media rendering are not established. Injected hook errors and actual filesystem/process evidence are labeled separately. Native tests and CLI prove no WebView, microphone, print, packaged ACL or media compatibility behavior.
